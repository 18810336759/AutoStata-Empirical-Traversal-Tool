# 结果复现与展示

## 目的与边界

本 skill 服务于“研究者选定一条已执行设定，然后理解、复跑、核对并展示结果”。它不是从 `merged_require_results.xlsx` 自动批量生成所有可能的 do 文件，也不以显著性为依据替用户挑选模型。用户每次指定一个或少量公共设定；程序读取当次运行证据，生成可审阅的 Stata 文件；研究者实际执行并检查结果；只有核验后的估计值才能进入论文表格。

本目录现有 `reproduction.yaml` 和 `run_reproduction.py`。生成器支持线性、多解释变量线性及单解释变量 U 型/倒 U 型主效应，以及线性、U 型/倒 U 型基础关系的线性调节；从选定历史批次的机器文件生成两版 do，并在用户实际运行 Stata 后读取结构化估计值制表。它**不会自动执行 do**。中介、非全样本缩尾或特殊插值边界等尚未实现，应明确报错，不套用相似模板。已有手工示例 `SPEC_309.do` 不是生成器模板。

阅读相关约定时，优先看 [基准检验手册](../基准检验/全局.md)、[结果整合说明](../基准检验/skill/result_synthesis/result_synthesis.md) 和 [论文表格规范](../../回归结果输出/输出.md)。只读取本次需要的模块 YAML、历史快照、处理定义和机器结果，不把整批大表放进 AI 上下文。

## 谁负责什么

| 角色 | 责任 |
| --- | --- |
| 研究者 | 审核数据来源和前置样本筛选，指定批次与设定，确认变量定义、理论方向、控制变量、固定效应与标准误是否适合论文；运行并审阅 Stata 输出，决定能否正式报告。 |
| 确定性程序（待实现） | 根据历史快照和精确模型项生成代码；检查数据、配置和模型 ID；记录两版口径差异；读取实际 Stata 估计值并生成结构化结果及表格。相同输入应产生相同代码。 |
| AI 助手 | 帮用户定位设定、解释代码和差异、分析运行失败及审阅异常；遇到不支持的模型形式应指出并协助扩展规则，不可凭综合表文字猜公式或虚构回归数值。 |

skill 可以协助选择和审阅，但**未经用户明确要求，不自动安装 Stata 扩展、不执行 do 文件、不覆盖旧输出，也不改动原始数据或基准检验配置**。用户同意生成文件不等于同意运行回归或修改研究设定。

## 用户如何使用

1. **选结果。**优先提供 `run_id + specification_id`；也可给出 `SPEC_309` 一类“模型合并ID”、综合表的一行或 `case_id`。后两者只是查找入口，程序必须解析并展示最终的 `run_id`、`specification_id`、输入数据指纹和模型清单，请用户核对。展示编号可能随重跑变化，不应单独作为复现身份。
2. **选范围。**选择“精确复现”“简明复测”或“两版”，以及要复跑的假设。默认精确版只针对该设定已经存在的 C 阶段模型；如要求补跑缺少 C 的假设，单列为“定向补充复测”。论文表名、变量展示名和需要并列的模型可由用户确认。
3. **核对方案。**生成代码前列出每个假设的因变量、核心项、平方项/交互项、全部控制变量、样本门槛、处理方案、固定效应、标准误、历史状态、预期 N 和数据来源。缺失、冲突或不支持的内容应停止并说明原因，不默认补猜。
4. **审阅并运行。**阅读 do 文件中每一步的“做什么、为何做、如何判断”；从头到尾在合适的 Stata 环境执行，检查日志中的错误、各模型 N、关键系数、标准误和 p 值。简明版的结果与 Python 不一致时，先检查已列明的处理口径差异，不把差异直接判成程序错误。
5. **看表并确认。**只有运行成功且通过约定校验的模型才进入“已复现”论文表。未运行、运行失败、缺少历史 C 或数值不一致的模型必须保留状态和原因，不静默删除；研究者最终确认表题、变量名、脚注、显著性说明与论文叙述。

最少输入是明确的一条设定身份、可读取的本轮数据及结果目录、所需版本。若用户只粘贴综合表的一行，仍要回到机器文件核对，不以粘贴文本作为唯一证据。若 `display_case_manifest.json` 没有案例，仍允许按 `run_id + specification_id` 定位；不能把 `case_id` 作为唯一入口。

当前命令入口（在项目根目录执行，或给 `--config` 指定其他 YAML）：

```bash
.venv-macmini/bin/python 回归结果解读/结果复现/run_reproduction.py
# 审阅并在 Stata 中分别运行输出的 exact.do、beginner.do 后：
.venv-macmini/bin/python 回归结果解读/结果复现/run_reproduction.py --collect
```

默认 `overwrite_existing=false`；再次生成同一目录会停止，已存在的论文表也不会被收集命令静默覆盖。运行 do 前请检查其原始数据路径和 Stata 扩展；简明版需要已安装的 `winsor2`、`reghdfe`。

## 证据与生成步骤

1. **定位并校验批次。**读项目 `run_manifest.json`、各效应 `run_record.json` 和当前数据文件；核对 `run_id`、数据 SHA-256、公共设定指纹、模块运行实例、配置快照和机器文件清单。历史结果若与目标批次不一致，停止生成“精确复现”声明。
2. **提取单条设定。**用 `specification_id` 从 `merged_*_results`、`specification_index.csv`、`hypothesis_results.csv`、`standardized_results.csv` 取得精确 `model_id`、阶段、通过标签、公式、生成项、N、控制组合及样本身份；读取对应 `preprocessing_definitions.json` 和运行时 YAML。`full/require/strong/weak` 是设定筛选表，不是逐项回归公式或系数来源。
3. **建立复现方案。**形成小型结构化清单：一条模型一条记录，包含公式和项定义、每模型自己的核心变量、可处理变量、处理顺序、完整案例条件、估计器、预期结果与历史状态。不同模型不能因为 `specification_id` 相同就强行使用同一最终样本。
4. **分别生成两版 do。**同一份方案驱动两种代码风格；命令生成由程序完成，模板只负责文件布局和说明文字。所有 do 文件逐段解释目的、输入、判断标准与可能的差异；原始变量尽量保留原名，只给新项起清楚的名字。
5. **执行后验收。**将 Stata 实际估计值输出为结构化文件并与历史结果核对：先比数据身份、N 和公式，再比关键系数、标准误、p 值；只对数值误差设置明示容差。不通过时记录具体差异和原因，不生成“复现成功”的结论。
6. **生成论文表。**从已核验的结构化估计值制作回归表，再按 `输出.md` 形成三线表；保留审计清单，让每个表格列都能追溯到 do、日志、模型及设定。

不要在对话中展开整份 `merged_require_results.xlsx`。程序按 ID 精确读取一行及相关模型，AI 只接收摘要、异常和最终路径；这是节省 token 的主要方式。

## 两版 do 文件的含义

### 精确复现版

- 目标是复建**历史已执行的 C 阶段模型**，采用其真实数据与运行快照，而非当前 YAML 后来可能改过的值。
- 顺序与共享预处理一致：原始核心变量有效年份门槛 → 企业内按真实年份插值 → 配置允许的变量按相同范围和分位点缩尾 → 构造平方项/交互项 → 当前模型完整案例 → 估计。
- 边界缺失、最大缺口、分位点算法、中心化时点、固定效应和标准误均按历史定义实现。若 Stata 做不到等价，应停下或如实标记近似，不能称为精确复现。
- 每个模型单独从原输入开始；保留历史模型 ID、预期 N 和校验值。缺少历史 C 结果的假设不伪装成已有模型。

### 初学者简明复测版

- 目标是帮助用户理解并额外检验指定设定下的假设；可按用户要求覆盖本轮启用的八条假设，包括历史缺少 C 的四条。
- 在门槛筛选之后，可采用 `bysort stkcd (year): ipolate 变量 year, gen(新变量) epolate`、`winsor2 变量, cuts(1 99) replace` 和 `reghdfe ..., absorb(stkcd year)` 等常用命令；先检查软件/扩展是否可用，明确是否需要用户安装。当前方案为全样本缩尾，不加 `by()`。
- 必须说明：`epolate` 首尾按斜率外推，而当前 Python 在相应条件下用最近观测值补端点；`winsor2` 与 Python 分位点算法可能不同；`reghdfe` 的 singleton、自由度及标准误处理也可能影响 N 和 p 值。**简明不是精确等价**。
- 不额外加 `vce(robust)`、`vce(cluster ...)` 或 `r`，除非目标设定本身如此；改变标准误属于新规格。中心化是减去均值，不是 `egen std()` 的标准化。
- U 型至少包括一次项与平方项；调节曲线还须包含配置要求的低阶项和平方项×调节变量。缺少 C 的补跑结果单列“新运行”，不得回填原 synthesis 的 `Strong pass` 或改变原批次状态。

当前已覆盖线性、U 型和倒 U 型主效应，以及线性调节和曲线关系调节。中介路径、二次调节及其他形式在生成器有对应规则和测试前应报告“不支持”，不可套用最相近模板。后续按模型形式增加小型命令构造规则，不把所有公式硬编码进一个巨大模板。

## 输出文件与阅读顺序

输出位于所选样本目录的 `<output.reproduction_subdir>/<run_id>/<specification_id>/`，不覆盖原 `result_synthesis/` 机器产物。

| 文件 | 内容与用途 |
| --- | --- |
| `reproduction_plan.json` | 选定设定、精确模型 ID、补跑清单、历史快照路径、数据指纹、模型项、处理定义及两版差异；生成前可审阅。 |
| `exact.do`、`beginner.do` | 分别为精确复现与简明复测；逐步中文解释及每个模型的 N/关键结果校验。只选择一版时只输出该版。 |
| `exact.log`、`beginner.log` | 用户执行 Stata 后的完整运行记录；生成 do 时尚不存在。 |
| `estimates_exact.csv`、`estimates_beginner.csv` | 实际运行后的结构化估计结果：假设 ID、检验项、系数、标准误、p 值、N、R²。只有完整执行 do 后才会导出。 |
| `<版本>_<效应类别>.rtf` | 若 Stata 已安装 `esttab`，do 在运行末尾将同类模型合并成 RTF；缺少扩展时提示并跳过，不影响机器结果。当前未纳入中介模型则不生成虚假的中介 RTF。 |
| `comparison.xlsx` 或 `comparison.csv` | 精确版与历史结果逐项对照；简明版列出口径差异。未执行时不制作数值比较。 |
| `audit.json`、`README_结果说明.md` | 记录来源、文件哈希、生成器版本、Stata/扩展版本、运行/核验状态、缺失或失败原因，以及用户该看哪张表。 |

do、日志和审计文件存于基准检验项目输出下的独立复现目录。**论文表格**按 [输出规范](../../回归结果输出/输出.md) 存在 `回归结果输出/` 下；每版在 `--collect` 核验后输出 `<模型合并ID>_<版本>_三类效应.xlsx`，含主效应、中介效应、调节效应三张工作表。空类别写明“本设定未纳入”，不伪造估计值。当前中介模型尚不支持生成 do；若选中设定含中介模型，程序会停止而不是遗漏。

论文回归表每列一个模型，系数与括号内标准误分两行，底部列出 N、R²、企业/年份固定效应和标准误口径。保留三线表、表题、显著性脚注和必要的方法注释；简明版需写明与 Python 不等价之处，补跑模型需标明“新运行”。三位小数若把小系数显示为 `0.000`，应提高该行精度或注明缩放单位，不能隐藏效应量。正式表格中的星号必须从该版实际 p 值计算，不照搬 synthesis 标签。

现有 [输出说明](../../回归结果输出/输出.md) 原先只定义已有 Excel 的排版。本 skill 的回归表由 `run_reproduction.py --collect` 从 Stata 结构化估计值直接生成，不调用名称为 `baseline regression table.py` 的旧排版脚本；不能直接把综合筛选表当论文回归表。

## 完成标准与注意事项

- 同一输入、同一历史快照和同一选择应生成稳定的方案及 do；缺配置、缺模型项、数据哈希不一致或不支持的形式必须有明确错误。
- 对每个历史 C 模型检查 N、关键系数、标准误和 p 值；误差容差及适用范围在报告中写明。若数值不一致，保留 do/log/诊断，不能只凭方向或显著性相同就称成功。
- 新补跑的假设与原有 C 结果分开；“没有 C”“运行失败”“未通过”“成功复现”是不同状态。
- 表格必须能回溯到实际 Stata 运行记录；未运行时最多生成 do 和待运行方案，不输出冒充实测的论文表。
- 禁止以筛查标签证明因果、严格 U 型或调节机制。曲线拐点、观察范围、稳健性、聚类标准误是否适当，仍由研究者决定并在正式研究中补充。
- 实现时先用一个真实设定做端到端验收，并用小型合成样本测试插值端点、分位点、固定效应、缺 C 的补跑、失败留痕和论文表空值处理。只验证文字模板不足以证明复现正确。
